# E2E Tests

End-to-end tests for the Mentor AI application using [Playwright](https://playwright.dev/) and the `@iblai/iblai-js/playwright` SDK.

## Prerequisites

- Node.js 18+
- pnpm
- Playwright browsers installed

```bash
pnpm install
npx playwright install
```

## Environment Setup

Copy the example env file and fill in your credentials:

```bash
cp e2e/.env.example e2e/.env.development
```

### Required Variables

| Variable              | Description                         | Example                      |
| --------------------- | ----------------------------------- | ---------------------------- |
| `AUTH_HOST`           | Auth service URL                    | `https://login.iblai.app`    |
| `MENTOR_NEXTJS_HOST`  | Mentor app URL (the app under test) | `https://mentorai.iblai.app` |
| `PLAYWRIGHT_USERNAME` | Test user email                     | `user@example.com`           |
| `PLAYWRIGHT_PASSWORD` | Test user password                  | `your-password`              |

### Optional Variables

| Variable                           | Description                                                                      |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| `AUTH_FLOW`                        | Auth flow type: `username_password` (default), `magic_link`, `sso`, `direct_sso` |
| `AUTH_IDP`                         | Identity provider for SSO flows                                                  |
| `CANVAS_URL`                       | Canvas LMS URL (for canvas embed tests)                                          |
| `CANVAS_EMAIL` / `CANVAS_PASSWORD` | Canvas credentials                                                               |
| `EMBED_URL`                        | URL to test embed widget injection                                               |
| `ENABLE_STRIPE_TEST`               | Set to `true` to run billing/subscription tests                                  |
| `IBL_MENTOR_DISABLED_TABS`         | Comma-separated list of disabled tabs                                            |
| `PLATFORM`                         | Platform identifier for auth setup                                               |

See [.env.example](.env.example) for the full list.

## Running Tests

```bash
# Run all tests
pnpm test:e2e

# Run with UI mode (interactive)
pnpm test:e2e:ui

# Run headed (see the browser)
pnpm test:e2e:headed

# Run a specific test file
pnpm test:e2e -- tests/chat/

# Run a specific project only
pnpm test:e2e -- --project=mentor-desktop-chromium

# Run with a specific grep pattern
pnpm test:e2e -- --grep "mentor card"
```

## Playwright Config

The config is generated by `createPlaywrightConfig` from `@iblai/iblai-js/playwright`. It creates projects for each browser (Chromium, Firefox, Safari) across two platforms:

| Platform | What it tests              | Dependencies   |
| -------- | -------------------------- | -------------- |
| `auth`   | Auth flows (signup, login) | None           |
| `mentor` | All mentor app tests       | `setup` (auth) |

Extra projects:

- **`snapshot-<browser>` / `residue-<browser>`** — Residue guard around every journey project (see [Test-data cleanup](#test-data-cleanup))
- **`mentor-public-views`** — Tests mentor pages viewable by unauthenticated users

## Test-data cleanup

Every agent (mentor) and project the suite creates must be gone when the run ends ([iblai-platform#2475](https://github.com/iblai/iblai-platform/issues/2475)). Four layers guarantee it; none of them is opt-in.

**1. One env contract for the DM API base.** `utils/dm-api.ts` → `dmBaseFromEnv()` resolves `DM_URL` (already includes `/dm`), then `E2E_DM_API_BASE`, then `NEXT_PUBLIC_API_BASE_URL + '/dm'`. When none is set, the base is observed from the app's own traffic (`observeDmBase(page)` is attached to every fixture page) and recorded in the run snapshot. Every cleanup path — fixtures, `project-cleanup.ts`, both sweepers, the residue teardown — uses this one resolution. Never load the app's root `.env` into Playwright: its `NEXT_PUBLIC_API_BASE_URL` points at production.

**2. Registration by construction.** `CreateMentorPage.createWithName` (so also `openAndCreate`) and `ProjectPage.createFromSidebar` call `registerMentor` / `registerProject` (`utils/resource-tracker.ts`) the moment the app confirms creation — before any assertion in the spec can fail. Each entry (`tenantKey`, id, name, owner, project) is kept in the worker's `ResourceTracker` and appended to the run ledger `e2e/.residue/<E2E_RUN_ID>.jsonl` (gitignored). Copies (journey 36) and any other creation path that bypasses the page objects must call `registerMentor(page, name)` explicitly.

**3. Worker bookkeeping, no mid-run deletes.** `fixtures/mentor-test.ts` has an auto worker fixture (`createdResources`) that configures this worker's `ResourceTracker` for the run. It no longer deletes anything when the worker shuts down: a mid-run delete from one worker's teardown raced other workers' in-flight tests against the same tenant (an auto-resolved mentor 404ing after a sibling worker deleted it). `MentorTracker.deleteAll` (older specs' `afterAll`) is now a no-op kept only so those specs keep compiling. Deletion happens exactly once, at the run level — layer 4.

**4. Run-level snapshot + teardown — the only deleter.** `journeys/residue.setup.ts` (`snapshot-<browser>`, depends on `setup-<browser>`, depended on by `mentor-desktop-<browser>`) records the admin user's mentor and project counts and the resolved DM base to `e2e/.residue/<runId>.<browser>.snapshot.json`. `journeys/residue.teardown.ts` (`residue-<browser>`, the snapshot project's `teardown`) runs once every journey project has finished: it deletes everything in the ledger for that browser (8 at a time), asserts every tracked id now returns 404, and prints `[e2e-residue] counts <browser>: mentors before=N after=M delta=D; projects …`. With `E2E_STRICT_COUNTS=1` a non-zero delta fails the run. `--project=mentor-desktop-<browser>` pulls both in through dependencies, so CI's per-browser loop needs no change.

**Backstop.** `globalTeardown` still runs `utils/mentor-sweeper.ts` and `utils/project-sweeper.ts`, which reap `E2E …`, `Copy of E2E …` and `Custom Copy …` mentors and `E2E Project …` projects older than 30 minutes (so a concurrent run's fresh objects are never touched). They now resolve the DM base through the same contract (env, else the run snapshot).

**Loud rule.** `failLoudly()` in `utils/resource-tracker.ts`: when `CI` or `DM_URL` is set, an unresolvable DM base, a failed delete, a skipped sweep or leftover residue **throws** (failing the teardown test / `globalTeardown`, so the run exits non-zero). Otherwise it is a `console.error` line prefixed `[e2e-residue]` — grep for it after a local run.

**Env vars**

| Var                 | Purpose                                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DM_URL`            | DM API base incl. `/dm` (e.g. `https://api.stg1.iblai.org/dm`). Set in CI; enables the loud rule                                                                                                         |
| `E2E_STRICT_COUNTS` | `1` → the residue teardown fails when the before/after mentor or project count differs                                                                                                                   |
| `E2E_RUN_ID`        | Optional run token; defaults to a timestamp chosen once in `playwright.config.ts`                                                                                                                        |
| `E2E_SKIP_SWEEP`    | `1` → both stale sweepers (`globalTeardown`) log and return without reaping or invoking the loud rule; the residue teardown still runs. Used by `e2e/scripts/bisect-residue.sh`                          |
| `ECOMMERCE_E2E`     | `1` → enables Journey 59's Stripe checkout lifecycle test; skipped otherwise (on top of the existing `DM_URL`/`ECOMMERCE_CREDIT_CLEANUP_TOKEN` gate) since most environments lack ecommerce/Stripe setup |

**Running locally against stg1 / .org with counts**

```bash
# e2e/.env.local holds the tenant creds + MENTOR_NEXTJS_HOST as usual
DM_URL=https://api.stg1.iblai.org/dm E2E_STRICT_COUNTS=1 PLAYWRIGHT_HTML_OPEN=never \
  pnpm exec playwright test --config e2e/playwright.config.ts --project=mentor-desktop-chrome
```

Read the `[e2e-residue] snapshot …`, `[e2e-residue] counts …` and `[e2e-residue] teardown … OK` lines at the end; anything prefixed `[e2e-residue]` that is not `OK` names the leaked object. Run one browser project per invocation when asserting counts — the snapshot is per user, and a second browser running concurrently perturbs it.

## Writing Tests

### Test File Location

Place test files in a feature directory under `e2e/tests/`:

```
e2e/tests/my-feature/
├── my-feature.spec.ts     # Test file (must end in .spec.ts)
└── helpers.ts             # Optional helpers specific to this feature
```

### Imports

```typescript
// Playwright test & expect
import { test, expect } from '@playwright/test';

// SDK utilities
import { logger, safeWaitForURL } from '@iblai/iblai-js/playwright';

// Shared env vars & helpers (from tests/utils.ts)
import {
  MENTOR_NEXTJS_HOST,
  authenticate,
  checkAdminStatus,
  waitForPageReady,
} from '../utils';

// Shared auth helpers (from tests/helpers.ts)
import {
  signUpWithEmailAndPassword,
  loginWithEmailAndPassword,
} from '../helpers';

// Reusable utility modules (from tests/utils/ directory)
import { fillCreateMentorForm } from '../utils/create-mentor';
import { navigateToLLMTab } from '../utils/navigate/navigate-to-llm-tab';
```

Note: `from '../utils'` resolves to `tests/utils.ts` (the main helpers file). `from '../utils/create-mentor'` resolves to `tests/utils/create-mentor.ts` (a sub-module).

### Test Template

```typescript
import { test, expect } from '@playwright/test';
import { MENTOR_NEXTJS_HOST, waitForPageReady } from '../utils';

test.describe('My Feature', () => {
  test.setTimeout(120_000);

  test.beforeEach(async ({ page }) => {
    await page.goto(MENTOR_NEXTJS_HOST);
    await waitForPageReady(page);
  });

  test('should do something', async ({ page }) => {
    // Test implementation
  });
});
```

### Available Helper Functions

From `tests/utils.ts`:

| Function                                | Description                                     |
| --------------------------------------- | ----------------------------------------------- |
| `authenticate(page)`                    | Full login flow via auth SPA                    |
| `reAuthenticate(page, platformUrl)`     | Re-login when tokens expire mid-test            |
| `waitForPageReady(page)`                | Wait for DOM complete + animations              |
| `checkAdminStatus(page)`                | Check if current user is admin via localStorage |
| `reliableClick(page, locator)`          | Click with retry logic and stability waits      |
| `reliableFill(page, locator, value)`    | Fill input with retry and validation            |
| `waitForDialogReady(page, locator)`     | Wait for dialog to be fully loaded              |
| `switchInstructorLearnerMode(page)`     | Toggle instructor/learner mode switch           |
| `expectNoAccessibilityViolations(page)` | Run axe-core accessibility scan                 |
| `searchMentor(page)`                    | Test mentor search flow                         |
| `mentorCardDisplay(page)`               | Verify mentor cards render correctly            |

### Tips

- Use `test.setTimeout()` for tests that involve auth redirects or AI responses (these can be slow)
- Use `waitForPageReady(page)` instead of `page.waitForLoadState('networkidle')` — SPAs keep making background requests that prevent networkidle from resolving
- Use `safeWaitForURL()` from the SDK for URL navigation waits — it handles both string patterns and regex
- Use `checkAdminStatus(page)` to conditionally run admin-only test steps
- Place feature-specific helpers in a `helpers.ts` file within the feature directory
- Auth state is saved per-browser in `playwright/.auth/` — tests in the `mentor` platform reuse this state
